# 技术核心与研发方向

## 已有实现

1. **本地来源适配与索引**：`SkillStore` 配置明确根；扫描器识别个人、系统和插件缓存，保留 SHA、变化摘要与历史会话口径。文件仅作为数据解析，不执行被审阅说明。当前是受限的 frontmatter 解析，不是任意 YAML 的完整编辑器。
2. **按任务理解技能**：Skill Engine 在当前 Codex 对话中按需读取少量相关技能，解释适用边界。结构规则与明确引用可确定性核对；语义关系需要原文和具体请求，不能只凭共享词汇判冲突。
3. **带证据的维护事务**：目标、案例、作者预期、引文与候选分开保存。写入前核对选中差异和当前 SHA，保留原文备份，再原子写入。description-only 不代表真实行为已保留。
4. **渐进界面**：React Flow 提供画布基础，项目自己设计分类、详情、来源状态和证据交互。地图不承担 Codex 原生路由，也不会执行图上的连线。

项目没有自研模型或已证实的新路由算法。当前价值来自把可核对证据与安全修改组成完整工作流。长期关键资产将是对应真实版本的任务—预期—实际选择—修改—结果案例，而不是无依据的“冲突分数”。

## 用户最短路径

连接本地目录 → 显式建立索引 → 按用途或具体任务找技能 → 核对相近技能边界 → 需要时选择最小修改 → 检查版本和备份 → 用真实任务验证结果。

普通用户只需浏览和讨论；维护表单在确实要修改时才出现。原文是唯一技能内容来源，编辑器意图独立保存，不进入 runtime 包。

## 下一步建议，尚未实现

- 首次启动显示实际根和范围，区分官方新目录、旧目录及项目目录，提供可预览的目录连接。
- 将 React Flow 的“重读目录”与“发现新技能”分开呈现，补首次导入入口。
- 对新技能提供通用用途分类，保留用户确认与手动调整；不能把分类当成调用证据。
- 建立真实 Codex 选择观察和产物检查，区分漏选、误选、合理组合，以及修改后丢失原有能力。
- 需要 ZIP 或外部目录安装时，另做目标检查、差异、冲突与确认流程，不能用索引操作暗中覆盖安装文件。

这些是研发方向，尚无跨用户安装、真实选择准确率或修改收益的验证结论。
